## 修复：巫师 3 无法从游戏库启动（用户反馈，根因 = 工作目录）

**诊断过程**：
- 应用日志显示启动成功（进程拉起、会话开始），但进程 ~24 秒静默退出（退出码 0），事件日志无崩溃。
- 对照实验（Start-Process + 35 秒观察）：
  - cwd = 游戏根目录（库内存的值）→ 35 秒内退出 ✗
  - cwd = exe 所在目录（bin/x64_dx12，即资源管理器双击的行为）→ 用户确认游戏正常启动 ✓
- 根因：巫师 3 的 exe 必须以自己所在目录为工作目录，游戏根目录会导致静默退出。

**修复**：
1. 数据：该记录 working_directory → exe 所在目录（SQL 直改）。
2. 源头：discovery/steam.rs 的扫描候选 working_directory 改为 exe 所在目录（此前是 install_dir）。
   其余来源（NVIDIA/Epic/目录扫描）不动 —— CS2/LoL/匹诺曹等以根目录为 cwd 均正常。

**教训**：heredoc 反斜杠转义会把路径写成 D:// 或 /，DB 写入必须用 chr(92) 拼接。
**版本号**：等用户确认是否升 1.0.1。

## 修复：长按拖拽没反应（用户反馈）

- 根因：Chromium 在 **mousedown 瞬间**快照「拖拽候选元素」，之后把 draggable 从 false 改成 true
  不会重新参与候选 —— 长按后再改属性的方式彻底无效。
- 修复：`draggable` 常驻 true，门槛移到 `onDragStart`：未完成 350ms 长按时 preventDefault
  取消拖拽（用户需松开重新长按）；达成长按后正常进入拖拽。行为不变、机制可靠。

## 修复二：长按拖拽改纯指针事件实现（用户反馈 HTML5 方案仍无反应）

- 结论：HTML5 拖拽与「长按后拖」手势天然冲突（两次尝试均失败），彻底弃用。
- 新实现（GameGrid 集中协调，纯指针事件）：
  - 卡片 onPointerDown → 上报 GameGrid → 350ms 定时器；达成后挂 window 级
    pointermove/pointerup 监听；press 期间移动 >8px 取消长按（防滚轮/误滑）。
  - 拖拽中：elementFromPoint + closest([data-card-id]) 实时定位悬停目标卡（虚线高亮）。
  - pointerup：按指针相对目标卡中点位置决定插前/插后 → commitReorder → onReorder 完整 id 序列。
  - 卡片 data-card-id 属性供命中检测；按在 button 上不进入拖拽。
- GameCard 回归纯展示 props（isDragged/isDropTarget/onCardPointerDown），无拖拽内部状态。
- 过程坑：重写 GameGrid 后漏 import Game 类型（tsc 报错即修）。
